# Glossary

| Term | Definition |
|---|---|
| ADR | Architecture Decision Record. A document that records an important decision, alternatives, rationale, and consequences. |
| AI | Artificial Intelligence. Software capabilities that generate predictions, recommendations, classifications, or other assisted outputs. |
| API | Application Programming Interface. A defined contract used by systems to exchange requests and data. |
| ASR | Architecturally Significant Requirement. A requirement that materially shapes the architecture. |
| BRD | Business Requirements Document. A document describing business needs, objectives, scope, stakeholders, and high-level requirements. |
| Cloud | Remotely hosted computing services used for processing, storage, analytics, integration, and management. |
| Drift | A change in data or model behaviour that may reduce AI performance over time. |
| Edge | Computing performed near estate devices or operations rather than only in the cloud. |
| Event | A record that something of business or operational significance occurred. |
| Family Pass | A ticket product that provides estate access for an eligible family group according to approved business rules. |
| Groundedness | The extent to which an AI response is supported by approved source information. |
| Human in the Loop | A control in which a person reviews, approves, corrects, or overrides an AI-supported outcome. |
| Idempotency | The ability to process a repeated request or event without creating an unintended duplicate outcome. |
| MQTT | A lightweight publish-subscribe messaging protocol commonly used by connected devices. |
| NFR | Non-Functional Requirement. A measurable quality requirement such as availability, performance, security, resilience, or maintainability. |
| Observability | The ability to understand system behaviour using logs, metrics, traces, alerts, and related signals. |
| PII | Personally Identifiable Information. Data that can identify or be linked to an individual. |
| Precision | The proportion of predicted positive results that are correct. |
| Recall | The proportion of actual positive cases correctly identified. |
| Resilience | The ability to continue, recover, or degrade safely when failures occur. |
| RTO | Recovery Time Objective. The target time to restore a service after disruption. |
| RPO | Recovery Point Objective. The maximum acceptable data-loss window after disruption. |
| Sensor Telemetry | Measurements or status data produced by estate devices. |
| SLO | Service Level Objective. A measurable reliability or performance target for a service. |
| Traceability | The ability to connect a requirement to its source, design decision, implementation, and test evidence. |
| Visitor Flow | Aggregated movement or occupancy information used to understand how visitors use estate areas. |
| Zero Trust | A security approach that requires explicit verification, least privilege, and continuous evaluation rather than implicit trust. |
